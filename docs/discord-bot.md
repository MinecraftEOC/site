## Что это и зачем

Пользователь сайта может **привязать** свой аккаунт к Discord. Схема:

1. На сайте пользователь запрашивает одноразовый **код**.
2. Идёт в определённый **канал** Discord-сервера, где бот держит закреплённое
   сообщение-панель с кнопкой **«Привязать аккаунт»**, и жмёт её.
3. Открывается **модальное окно** с полем «Код с сайта» — пользователь вводит код
   и отправляет.
4. Если код верный и не протух — аккаунты связываются: в БД сохраняются данные
   Discord-пользователя, статус привязки становится `LINKED`.

Ввод кода реализован через **кнопку + модальное окно**, а не обычное сообщение и
не slash-команду. Что это даёт:

- **Канал можно наглухо закрыть на запись** (`Send Messages` запрещён всем) — при
  этом кнопка и модалка продолжают работать, им это право не нужно. Так в канале
  физически не может появиться посторонний текст.
- Не требуется привилегированный интент `MESSAGE CONTENT`.
- Ответ бота **эфемерный** — виден только вызвавшему, код не светится в общем чате.
- Игроку не надо помнить синтаксис `/verify code:...` — просто кнопка и поле ввода.

> 📌 **Почему не slash-команда.** У Discord «писать текст» (`Send Messages`) и
> «пользоваться slash-командами» (`Use Application Commands`) — разные права, но
> на практике полностью закрытый на запись канал глушит и команды. Кнопке и
> модалке для работы достаточно того, что игрок **видит** канал, поэтому она
> надёжно работает в канале только для чтения. Историческая slash-команда
> `/verify` удалена.

## Архитектура

Бот живёт **внутри Nitro** как плагин (`server/plugins/discord-bot.ts`), а не
отдельным сервисом. Что это даёт:

- **Один процесс, один деплой** — бот стартует вместе с сервером сайта.
- **Прямой доступ к `prisma`** — бот работает с БД напрямую, без HTTP-моста между
  ботом и бэкендом.

Бот подключается к Discord **исходящим постоянным WebSocket-соединением
(Gateway)**. Discord сам присылает по нему события (нажатия кнопок, отправку
модалок), поэтому **публичный URL / туннель не нужны** — всё работает даже с
локалхоста.

> ⚠️ **Хостинг:** такой встроенный бот требует long-running Node-сервера
> (Nitro preset `node-server`, self-host / VPS). На serverless (Vercel/Netlify)
> постоянное Gateway-соединение работать не будет.

## Как работает привязка (поток)

```
Сайт                          Бэкенд (Nitro)                Discord
 │                                  │                          │
 │  «Привязать Discord»             │                          │
 ├─── POST /api/discord/link ──────►│                          │
 │                                  │ generateVerifyCode()     │
 │                                  │ upsert DiscordAccount    │
 │◄──── { code, expiresAt } ────────┤ (status=PENDING)         │
 │                                  │                          │
 │  показываем код + таймер         │                          │
 │  и поллим статус каждые 5–10 с   │                          │
 │                                  │                          │
 │   игрок жмёт кнопку «Привязать аккаунт» в канале ───────────►│
 │                                  │◄── Interaction (кнопка) ──┤
 │                                  ├── showModal() ───────────►│
 │            игрок вводит код в модалке и отправляет ─────────►│
 │                                  │◄── Interaction (модалка) ─┤
 │                                  │ linkDiscordByCode()      │
 │                                  │ проверка + транзакция    │
 │                                  │ (status=LINKED)          │
 │                                  ├──── эфемерный ответ ─────►│
 │                                  │                          │
 │  поллинг GET /api/discord/status → status === 'LINKED'      │
 │  → останавливаем поллинг, обновляем UI                      │
```

## API эндпоинты сайта

Оба эндпоинта защищены `requireUser` (нужна активная сессия). Типы ответов лежат
в `shared/types/response.ts` и используются как на сервере (явный тип возврата
хендлера), так и на клиенте (`$fetch<IXxx>(...)`).

### `POST /api/discord/link` — запросить код

- Если аккаунт уже `LINKED` → `409` (`DISCORD_ERRORS.ALREADY_LINKED`).
- Иначе генерирует новый `verifyCode` + `verifyExpiry` (now + TTL) и **upsert**-ит
  строку `DiscordAccount` по `userId` (status остаётся `PENDING`).
- Повторный вызов **перезаписывает** старый код новым (старый сразу инвалидируется).
- Ответ — `IDiscordLinkResponse`: `{ code, expiresAt }` (дата — ISO-строка).

### `GET /api/discord/status` — узнать статус (для поллинга)

- Возвращает текущий статус привязки как **данные**, всегда `200`:
  `IDiscordStatusResponse` — `{ status }` (`PENDING` / `LINKED`).
- Это **статус-эндпоинт**: он не бросает ошибку на `LINKED` — наоборот, именно
  этого значения ждёт фронт, опрашивая эндпоинт.

### Поллинг на фронте

После показа кода фронт опрашивает `/status` каждые 5–10 секунд:

```ts
const { status } = await $fetch<IDiscordStatusResponse>('/api/discord/status');
if (status === 'LINKED') {
    stopPolling(); // привязка прошла — обновляем UI
}
```

Условия остановки поллинга:

- `status === 'LINKED'` — успех;
- истёк `expiresAt` из ответа `/link` — код протух, показать «запросите код заново»;
- размонтирование компонента — обязательно очищать интервал (и желательно ставить
  на паузу при `document.hidden`, чтобы фоновая вкладка не слала запросы).

## Настройка в Discord Developer Portal

Разово, вручную. В итоге получаешь 4 значения для `.env` (см. следующий раздел).

### 1. Создать приложение

1. Открой **https://discord.com/developers/applications**.
2. Справа вверху — **New Application**, задай имя, прими соглашение → **Create**.

### 2. Application ID → `NUXT_DISCORD_CLIENT_ID`

1. Вкладка **General Information** → поле **Application ID** → **Copy**.

### 3. Бот и токен → `NUXT_DISCORD_BOT_TOKEN`

1. Вкладка **Bot**. Если бот не создан автоматически — **Add Bot**.
2. Раздел **Token** → **Reset Token** → подтвердить → **Copy**.
   Токен показывается **один раз** — сразу копируй.
3. **MESSAGE CONTENT INTENT включать НЕ нужно** — используем кнопку и модалку.

> 🔒 Токен — это пароль бота. Не коммить в git (у нас он только в `.env`).
> Потерял — снова **Reset Token**, старый перестанет работать.

### 4. Ссылка-приглашение

1. Вкладка **OAuth2 → URL Generator**.
2. **Scopes:** ☑ `bot`, ☑ `applications.commands`.
3. **Bot Permissions:** ☑ `View Channels`, ☑ `Send Messages`,
   ☑ `Read Message History`.
   - `Send Messages` нужно **самому боту**, чтобы один раз запостить панель с
     кнопкой (это не даёт право писать игрокам — их права настраиваются отдельно).
   - `Read Message History` нужно, чтобы при старте бот нашёл уже опубликованную
     панель и не постил её повторно.
4. Внизу **Generated URL** → **Copy**.

### 5. Пригласить бота на сервер

1. Открой скопированную ссылку в браузере.
2. В окне **Add to Server** выбери свой сервер → **Continue** → **Authorize**.

> Достаточно права **«Управление сервером» (Manage Server)** — оно входит в права
> администратора. Быть владельцем сервера не обязательно. Если приложение с
> выключенным **Public Bot** — ничего страшного, ты как владелец бота всё равно
> его добавишь.

### 6. Включить Developer Mode

Нужно, чтобы копировать ID. Discord → **Настройки пользователя → Advanced →
Developer Mode** (включить).

### 7. ID сервера → `NUXT_DISCORD_GUILD_ID`

Правый клик по иконке сервера → **Copy Server ID**.

### 8. ID канала → `NUXT_DISCORD_CHANNEL_ID`

Правый клик по текстовому каналу, где будет висеть панель с кнопкой →
**Copy Channel ID**.

### 9. Права канала верификации (ключевой шаг)

Именно эта настройка закрывает канал от постороннего текста, но оставляет кнопку
рабочей. В настройках канала → **Права доступа**:

| Роль | Право | Значение |
|---|---|---|
| `@everyone` | Просматривать канал | ✅ разрешить |
| `@everyone` | Отправлять сообщения | ❌ запретить |
| роль бота | Отправлять сообщения | ✅ разрешить |
| роль бота | Читать историю сообщений | ✅ разрешить |

- Игроки **видят** канал и кнопку, но **не могут писать** — модалке право на
  запись не нужно, поэтому кнопка продолжает работать.
- Боту `Отправлять сообщения` нужно, чтобы запостить саму панель, а
  `Читать историю` — чтобы не дублировать её при перезапусках.
- Право `Использовать команды приложений` для этого канала больше не требуется —
  slash-команды не используются.

## Переменные окружения

Секреты в код не пишем — они живут в `.env` (файл в `.gitignore`).

```dotenv
NUXT_DISCORD_BOT_TOKEN=токен_из_шага_3
NUXT_DISCORD_CLIENT_ID=application_id_из_шага_2
NUXT_DISCORD_GUILD_ID=id_сервера_из_шага_7
NUXT_DISCORD_CHANNEL_ID=id_канала_из_шага_8
```

В `nuxt.config.ts` ключи объявлены пустыми строками — это **плейсхолдеры**. Nuxt
подставляет реальные значения из env по правилу **`NUXT_` + КЛЮЧ_В_СНЕЙК_КЕЙСЕ**:

| Ключ в `runtimeConfig` | Env-переменная |
|---|---|
| `discordBotToken` | `NUXT_DISCORD_BOT_TOKEN` |
| `discordClientId` | `NUXT_DISCORD_CLIENT_ID` |
| `discordGuildId` | `NUXT_DISCORD_GUILD_ID` |
| `discordChannelId` | `NUXT_DISCORD_CHANNEL_ID` |

В коде значения читаются через `useRuntimeConfig()`.

## Как устроен код бота

Файл `server/plugins/discord-bot.ts` — Nitro-плагин, выполняется один раз при
старте сервера.

На верхнем уровне модуля (один раз) собираются **переиспользуемые заготовки**:
кнопка `verifyButton` + ряд `panelRow`, текст панели `panelContent` и модалка
`verifyModal` с полем ввода кода. Их `customId` берутся из `VERIFY_CUSTOM_ID`,
тексты — из `VERIFY_PANEL`. Длина поля жёстко ограничена `VERIFY_CODE_LENGTH`.

> Панель отправляется **обычным текстовым сообщением** (не embed) намеренно: для
> embed нужно отдельное право «Встраивать ссылки» (`Embed Links`), а простому
> сообщению с кнопкой хватает `Send Messages`. Так меньше требований к правам.

1. **Проверка env.** Если хоть одного из 4 значений нет — плагин пишет
   предупреждение и выходит (`return`). Сайт при этом работает, бот — нет.
2. **Singleton через `globalThis`.** Ссылка на клиент хранится в глобальном
   объекте, чтобы HMR в dev не создавал повторные подключения к Gateway (тот же
   приём, что и для `prisma`).
3. **Создание клиента** с интентом `Guilds` — этого достаточно для приёма нажатий
   кнопок и отправки модалок. Привилегированные интенты не используются.
4. **На событии `ClientReady`:**
   - **чистим slash-команды** — `rest.put(Routes.applicationGuildCommands(...), { body: [] })`
     удаляет устаревшую `/verify` из гильдии (на случай, если она осталась с
     прошлых версий);
   - **публикуем панель** — достаём канал `NUXT_DISCORD_CHANNEL_ID`, проверяем
     `channel.isSendable()` и вызываем `ensureVerifyPanel()`.
5. **`ensureVerifyPanel()`** делает публикацию идемпотентной: тянет последние
   50 сообщений канала, ищет **своё** сообщение с кнопкой (`author.id` = id бота и
   среди компонентов есть кнопка с `customId === VERIFY_CUSTOM_ID.BUTTON`). Если
   нашёл — ничего не делает; если нет — постит сообщение с кнопкой. Так рестарты
   сервера не плодят дубли панели.
6. **Обработка `InteractionCreate`** (два ветвления):
   - **нажатие кнопки** (`isButton()` + `customId === BUTTON`) → открываем модалку
     через `interaction.showModal(verifyModal)`;
   - **отправка модалки** (`isModalSubmit()` + `customId === MODAL`) → достаём код
     из поля `interaction.fields.getTextInputValue(CODE_INPUT)`, вызываем
     `linkDiscordByCode(code, { id, username, avatar })` и отвечаем **эфемерно**:
     успех либо текст причины по `DISCORD_ERRORS[result.reason]`;
   - любые неожиданные ошибки логируются, пользователю — нейтральный текст.
   - Проверка канала больше не нужна: кнопка существует только в сообщении внутри
     канала верификации, вызвать модалку из другого места нельзя.
7. **`client.login(token)`** открывает Gateway-соединение. После успешного логина
   срабатывает `ClientReady` (чистка команд + публикация панели) и начинают
   приходить взаимодействия. При ошибке логина ссылка в `globalThis` сбрасывается.

Сама привязка — в `server/utils/discord.ts`, функция `linkDiscordByCode`:
ищет `DiscordAccount` по коду со статусом `PENDING` и не протухшим сроком,
проверяет, что Discord не занят другим аккаунтом, и в одной транзакции
(`prisma.$transaction`) проставляет `LINKED` + данные Discord, гася код.
Функция **автоимпортируется** Nitro, поэтому в плагине вызывается без `import`.

## Внесение изменений: что где менять

Настройки бота живут в **трёх местах** (код / Developer Portal / сервер Discord),
и не всё «подтягивается само».

| Что меняешь | Код | Сервер Discord | Портал |
|---|:---:|:---:|:---:|
| Имя / аватар / описание бота | — | — | ✔ (подтянется само) |
| Токен (сброс) | `.env` | — | ✔ |
| Интенты | ✔ `intents: [...]` | — | ✔ (оба, синхронно) |
| Права / scopes | — | переприглашение или роль | ✔ (новая ссылка) |
| Тексты панели/кнопки/модалки, `customId` | ✔ `VERIFY_PANEL` / `VERIFY_CUSTOM_ID` | — | — |
| Права канала (кто может писать) | — | ✔ настройки канала | — |

Ключевые правила:

- **Косметика** (имя/аватар/описание) — только портал, подтянется сама.
- **Интенты** — включать и в портале, **и** в коде (`new Client({ intents: [...] })`),
  значения должны совпадать, иначе бот не залогинится или не получит события.
- **Права/scopes** — это не код: сгенерируй новую ссылку-приглашение и пройди по
  ней заново (бот не задублируется), либо выдай право его роли в настройках сервера.
- **Панель, кнопка, модалка** (тексты, подписи, `customId`) определяются **только
  в коде** — в портале раздела для этого нет. Правишь `VERIFY_PANEL` /
  `VERIFY_CUSTOM_ID` и **перезапускаешь** сервер.
- **Обновление уже висящей панели.** `ensureVerifyPanel()` не *переписывает*
  существующее сообщение — если панель в канале уже есть, оно останется старым.
  Изменив тексты/кнопку, вручную удали старое сообщение-панель в канале и
  перезапусти сервер — бот опубликует новое.
- **Права канала** (кто может писать) — это настройки самого канала на сервере, а
  не код и не портал (см. раздел «Права канала верификации»).

## Локальное тестирование

Публичный URL не нужен — бот сам «дозванивается» до Discord.

1. Заполни `.env` (4 значения выше). Локальный Postgres должен быть поднят
   (`DATABASE_URL`).
2. `bun run dev`.
3. После логина бот опубликует в канале **сообщение-панель с кнопкой «Привязать
   аккаунт»** (если её там ещё нет). Ошибок вида `Канал верификации недоступен`
   в консоли быть не должно.
4. Проверить бота можно **не дожидаясь фронта**: в `bun run db:studio` создай
   строку `DiscordAccount` со статусом `PENDING`, известным `verifyCode` и
   `verifyExpiry` в будущем. Затем нажми кнопку в канале, введи код в модалке и
   отправь — статус должен стать `LINKED`.
5. Негативные кейсы: неверный/просроченный код → «Код неверный или устарел»;
   тот же Discord на второй аккаунт → «Этот Discord уже привязан…».

> ⚠️ Не держи локального и продового бота с **одним токеном** одновременно — будут
> две Gateway-сессии, и на нажатие ответят обе. Для локалки заведи отдельный
> тестовый бот/токен (желательно и отдельный тестовый сервер).

## Диагностика проблем

| Симптом | Вероятная причина |
|---|---|
| `[discord-bot] Пропущены env-переменные Discord — бот не запущен` | Не создан `.env`, опечатка в имени переменной или dev-сервер не перезапущен после правки `.env` |
| `Не удалось залогиниться в Discord` | Неверный/сброшенный токен |
| `Канал верификации недоступен или в него нельзя писать` | Неверный `CHANNEL_ID`; бот не видит канал или ему запрещено `Отправлять сообщения` в нём |
| `Не удалось опубликовать панель верификации` | Боту не хватает прав `Send Messages` / `Read Message History` в канале |
| `Не удалось опубликовать панель… DiscordAPIError[50013]: Missing Permissions` | У бота в канале нет `Send Messages` или `Read Message History`. Права меняли уже после старта бота → перезапусти процесс (`pm2 reload site`): панель постится только на `ClientReady` |
| Панель с кнопкой не появляется в канале | Бот не в сервере; не совпадает `GUILD_ID`/`CHANNEL_ID`; не сработал `ClientReady`; нет прав на запись в канал |
| Панель задублировалась | Панель есть, но бот её не «увидел»: нет права `Read Message History`, либо старую панель постил другой бот/токен |
| По кнопке ничего не происходит | Панель осталась от старой версии кода с другим `customId` — удали сообщение и перезапусти сервер |
| На нажатие отвечают «два бота» | Запущены две сессии с одним токеном (dev + prod / два процесса) |
| Всегда «Код неверный или устарел» | Код протух (TTL), уже использован, или в БД нет записи `PENDING` с таким `verifyCode` |
