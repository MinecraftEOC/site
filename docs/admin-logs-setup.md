# Подключение и сопровождение раздела «Логи» (`/account/admin/logs`)

Раздел «Логи» позволяет администраторам сайта (`UserRole.ADMIN`) просматривать серверные журналы Minecraft-сервера в режиме **read-only** через защищённые серверные ручки сайта (`/api/admin/logs/*`), которые обращаются к внутреннему сервису `data-exchanger` (`/api/logs/*`).

---

## 1. Настройка источника (`data-exchanger`)

1. В файле `/minecraft/data-exchanger/.env.sheets` добавьте переменные:
   ```dotenv
   LOGS_API_ENABLED=true
   LOGS_ROOT=/minecraft/server/world/customnpcs/logs
   LOGS_API_TOKEN=<сгенерируйте отдельный токен не короче 32 байт: openssl rand -hex 32>
   ```
   > **Важно:** `LOGS_API_TOKEN` обязан отличаться от `EXPORT_API_TOKEN`.

2. Права доступа на файловой системе:
   - Процессу `data-exchanger` нужны **только права на чтение**:
     - `r-x` (`0750` / `0755`) на каталог `LOGS_ROOT` и подкаталоги категорий (`errors`, `system`, `states`, `damage`, `locks`, `api`, `checks`, `combat`);
     - `r--` (`0640` / `0644`) на создаваемые `.log` файлы.
   - Убедитесь, что `umask` процесса игрового сервера создаёт новые файлы `.log` и ротированные архивы с правом чтения для пользователя/группы `data-exchanger`.

3. Перезапустите API `data-exchanger` (`./run_api.sh`) и проверьте ответ:
   ```bash
   curl -i -H "Authorization: Bearer <LOGS_API_TOKEN>" http://127.0.0.1:8787/api/logs/categories
   ```

---

## 2. Настройка сайта (`site`)

1. В `.env` сайта добавьте приватные переменные окружения Nuxt:
   ```dotenv
   NUXT_LOGS_API_BASE_URL=http://127.0.0.1:8787
   NUXT_LOGS_API_TOKEN=<тот же LOGS_API_TOKEN из .env.sheets>
   NUXT_LOGS_API_TIMEOUT_MS=8000
   ```
   > В режиме локальной разработки (`bun run dev`), если `NUXT_LOGS_API_BASE_URL` оставлен пустым, сайт автоматически отдаёт демонстрационный набор логов по всем 8 категориям. В production (`bun run build`) при пустых переменных ручки возвращают `503`.

2. Пересоберите и перезапустите сайт:
   ```bash
   bun run build
   pm2 restart eoc-site --update-env
   ```

3. Маршрутизация nginx:
   - На боевом сервере location `/api/admin` проксируется в Nuxt (`127.0.0.1:3000`), поэтому запросы `/api/admin/logs/*` не конфликтуют с GravitLauncher (`/api`).

---

## 3. Диагностика типовых проблем

- **В админке отображается `502 Ошибка подключения к источнику журналов`**:
  - Источник `data-exchanger` вернул `401` или `403` на внутренний запрос сайта.
  - Проверьте, что `NUXT_LOGS_API_TOKEN` в `.env` сайта в точности совпадает с `LOGS_API_TOKEN` в `.env.sheets`, и перезапустите оба процесса с обновлением окружения (`pm2 restart eoc-site --update-env`).
  - При этой ошибке сессия администратора на сайте **не сбрасывается**.

- **В админке отображается `503 Источник серверных журналов временно недоступен`**:
  - Проверьте, запущен ли процесс `data-exchanger`, включён ли `LOGS_API_ENABLED=true`, существует ли папка `LOGS_ROOT` и есть ли у процесса права `r-x` / `r--` на каталоги и файлы.

- **В категории не видны новые файлы**:
  - Нажмите кнопку **«Обновить»** в правом верхнем углу раздела «Логи» (сбрасывает 5-секундный кэш метаданных) и проверьте права чтения на новые файлы.

---

## 4. Перенос на отдельный физический сервер

Когда игровой сервер и `data-exchanger` переезжают на отдельный хост:

1. Разверните `data-exchanger` рядом с папкой логов игрового сервера и укажите актуальный `LOGS_ROOT`.
2. Организуйте закрытый канал связи между сервером сайта и сервером игры (рекомендуется WireGuard / приватная VLAN либо защищённый внутренний HTTPS-шлюз с фильтрацией по IP сервера сайта).
3. Измените в `.env` сайта только `NUXT_LOGS_API_BASE_URL` (например, на внутренний адрес в приватной сети) и перезапустите `pm2 restart eoc-site --update-env`. Изменений кода сайта не требуется.

---

## 5. Быстрый откат

- Чтобы мгновенно отключить чтение логов без остановки экспортов таблиц, установите `LOGS_API_ENABLED=false` в `.env.sheets` и перезапустите `data-exchanger`.
- Откат ветки сайта или отключение `LOGS_API_ENABLED` не затрагивает базу данных сайта и файлы игрового мира.
