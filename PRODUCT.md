# Эпоха Колонизации

«Эпоха Колонизации» (`eoc-rp.ru`) — сайт русскоязычного Minecraft RP-сервера в мире средневекового фэнтези. Он помогает новым игрокам познакомиться с миром и правилами, создать персонажа и скачать лаунчер, а администрации — модерировать заявки, публиковать материалы и просматривать игровые журналы.

## Пользователи и сценарии

- **Посетитель** знакомится с проектом, читает правила, новости и лор, проверяет онлайн игрового сервера и скачивает лаунчер для Windows, Linux или macOS.
- **Игрок** регистрируется по email, входит в личный кабинет и привязывает Discord через бота. При создании персонажа он пишет квенту (биографию), распределяет очки параметров и навыков, выбирает стартовые предметы и загружает скины. В кабинете видны статус заявки и замечания администрации. Игрок может доработать заявку после возврата и выбрать активный скин.
- **Администратор** просматривает список пользователей и анкеты персонажей, меняет статусы заявок и оставляет комментарии. В кабинете также можно создавать, редактировать и удалять новости и материалы лора, добавлять обложки и иллюстрации, искать и фильтровать записи игровых журналов.

## Бизнес-правила и ограничения

- Публичные страницы доступны без входа. Для личного кабинета нужна сессия сайта, а доступ к административным операциям проверяется на сервере по роли `ADMIN`.
- Для создания персонажа нужен привязанный Discord. Код привязки одноразовый и действует ограниченное время. Новый код заменяет предыдущий.
- У обычного игрока может быть один персонаж, занимающий игровой слот. Статусы `DEAD` и `UNAVAILABLE` освобождают слот. Владелец может редактировать анкету в статусах `UNVERIFIED` и `RETURNED`. Создание заявки требует хотя бы одного скина. У персонажа может быть до десяти скинов, а лаунчер получает один активный.
- Новости и лор публикуются из Markdown. Адрес материала определяется типом и уникальным внутри этого типа слагом. Правила игры хранятся в [content/rules.md](content/rules.md).
- Игровые журналы доступны администраторам только для чтения. Сайт запрашивает категории, файлы и страницы записей у `data-exchanger` из серверной части. Для локальной разработки предусмотрены демонстрационные записи при отсутствии настроенного источника.
- Серверная часть формирует токен сброса пароля. Отправка письма со ссылкой ещё не реализована.

## Технический стек и интеграции

- **Веб-приложение.** Nuxt 4, Vue 3, TypeScript, Pinia и SCSS на клиенте, Nitro на сервере. Схемы Zod и типы для клиента и API лежат в `shared/`. Для зависимостей и команд проекта используется Bun.
- **Данные.** PostgreSQL через Prisma. В базе хранятся пользователи, сессии, привязки Discord, персонажи и метаданные скинов и публикаций. Файлы скинов и изображения публикаций хранятся на диске.
- **Minecraft и GravitLauncher.** Сайт запрашивает статус игрового сервера и предоставляет внутреннее API для получения данных персонажа и списка его скинов. Лаунчер использует активный скин персонажа.
- **Discord.** Бот работает внутри Nitro и принимает коды привязки через Discord Gateway. Ему нужен постоянно работающий процесс сайта. [Документация Discord-бота](docs/discord-bot.md)
- **Игровые журналы.** Nitro обращается к внутреннему HTTP API `data-exchanger`. Адрес источника и токен задаются в приватной конфигурации сервера. [Подключение и сопровождение раздела «Логи»](docs/admin-logs-setup.md)
