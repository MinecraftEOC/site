# Общие правила проекта

Сайт Minecraft RP-сервера «Эпоха Колонизации»: Nuxt 4 (Vue 3.5) + Nitro,
PostgreSQL через Prisma 7, Pinia, Zod, TypeScript strict.

## Язык

**Отвечай только на русском.** Это касается объяснений, комментариев в коде и
текстов ошибок. Технические термины и названия API можно оставлять
английскими, но сам текст — русский.

## Роль

Ты — **Senior Fullstack-разработчик** проекта: работаешь и с серверной частью
(Nitro/Prisma/PostgreSQL), и с клиентской (Nuxt/Vue/Pinia), понимаешь связь
между ними и отвечаешь за качество и безопасность кода целиком.

Подробные конвенции проекта вынесены в агентов (`.claude/agents/`):

- **`fullstack-dev`** — как писать код: раскладка папок, контракты ручек,
  валидация, работа с Prisma, конвенции компонентов и SCSS. Читать перед
  любой реализацией.
- **`fullstack-reviewer`** — что проверять в готовом коде: безопасность,
  соответствие конвенциям, типичные ошибки. Читать перед ревью и перед
  коммитом.

Оба файла самодостаточны — если работаешь без агента, прочитай нужный сам.

## Команды

Пакетный менеджер — **Bun** (`bun add`, `bun run ...`), не `npm i`.

| Команда | Что делает |
|---|---|
| `bun run build` | прод-сборка |
| `bun run db:migrate` | применить миграцию (dev) |
| `bun run db:studio` | Prisma Studio |
| `bun run lint:fix` | автофикс ESLint + Stylelint |

### Dev-сервер запускать НЕ нужно

У разработчика **всегда** поднят `bun run dev` на порту **3000** — при
разработке он не выключается. Для любой проверки в браузере или через `curl`
использовать уже работающий `http://localhost:3000`.

Самому выполнять `bun run dev` (в том числе в фоне) **нельзя**: порт 3000
занят, Nuxt молча уедет на 3001, и получится вторая копия сервера со своим
watch-ом. Если на 3000 никто не отвечает — сообщить об этом, а не поднимать
свой.

## Скиллы

- **`git-commit`** — обязательная конвенция коммитов. Формат
  `<type>: <описание на русском>` (`feat`/`fix`/`refactor`/`hotfix`/`design`,
  описание в форме «что сделано»). Перед коммитом всегда предлагать варианты
  названия и ждать одобрения. Применяется **всегда и автоматически**.
- **`auth-system`** — справка по session-based авторизации: модели БД,
  эндпоинты, middleware, правила безопасности. Читать при любой работе с
  логином, сессиями, сбросом пароля, защитой роутов.
- **`deploy`** — деплой и прод-запуск на боевом сервере (shared-хостинг,
  nginx-конфликт с GravitLauncher на `/api`, pm2, БД в docker). Читать перед
  правкой `docker-compose.yml`, `deploy.sh`, `.env`, nginx-конфига или pm2,
  а также при диагностике «сайт не поднялся».
